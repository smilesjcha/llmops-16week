# 10·11·12주차의 차이와 중복 점검

점검 기준: 공개된 10주차 PDF 80쪽·Notebook 6개, 11주차 HTML 64쪽·Notebook 10개, 12주차 HTML 64쪽·Notebook 5개. 검토일 2026-11-15.

## 같은 서비스, 서로 다른 검증 단위

| 구분 | 10주차 · 배포와 실행 관찰 | 11주차 · 오프라인 품질 검증 | 12주차 · 온라인 실험 |
|---|---|---|---|
| 핵심 질문 | 정상 처리·장애 진단·복구가 가능한가? | 답변이 근거·정확성·기권 기준을 만족하는가? | 변경이 사용자 결과를 개선하는가? |
| 비교 단위 | 요청·작업 구간·시간 창 | 같은 고정 질문의 답변 | 무작위로 배정한 사용자 |
| 주요 입력 | 실행 설정·정상/장애 요청 | 질문·참고 근거·버전별 실제 응답 | 진입 사용자·배정·피드백·관찰 기간 |
| 주요 증거 | 로그·Trace·지표·복구 후 정상 요청 | 문항별 평가·실패 분류·회귀 결과 | SRM·분모·차이·신뢰구간·보호 지표 |
| 실습 도구 | FastAPI, Docker, Prometheus, Trace 개념 | Ollama, Langfuse, 고정 평가 세트 | 고정 배정, 사용자 집계, 통계·판정 코드 |
| 주요 실패 | 502/504·준비 실패·상태 누출 | 잘못된 답변·누락·기권 실패·평가자 오판 | 배정 누락·조건 혼합·편향된 분모·조기 종료 |
| 완성할 결과 | 어떤 버전이 왜 실패했고 어떻게 복구했는지 | 어떤 질문에서 실패했으며 후보가 기준을 통과했는지 | 어떤 사용자에게서 어떤 효과·위험을 확인했는지 |

10주차에도 “HTTP 200이 답변 정확성을 보장하지 않는다”는 고정 문장 검사가 있습니다. 11주차는 이를 질문·정답 근거·검색·기권·실제 모델·평가자 검증으로 확장합니다. 12주차는 이 품질 기준을 사전 조건으로 이어받아 사용자 행동을 비교합니다.

## 특히 혼동하기 쉬운 A/B/C와 A/B

**11주차 Langfuse A/B/C:** 선택한 고정 회귀 질문 4개를 A·B·C에 각각 입력합니다. 답변·점수·실패 이유를 같은 문항 기준으로 비교합니다. 무작위 사용자 실험이 아닙니다.

**12주차 A/B:** 실험에 진입한 사용자를 A 또는 B에 고정 배정하고 첫 요청 이후 30분의 해결 확인을 비교하는 설계입니다. 같은 사람이 매 요청마다 버전을 바꾸지 않습니다. 수업의 2400명 CSV는 이 설계를 배우기 위한 합성 자료이며 실제 제품 성과가 아닙니다.

Ollama에 같은 질문을 두 번 보내는 12주차 05번도 그 자체로 사용자 A/B 실험은 아닙니다. 온라인에 투입할 후보의 실제 응답을 확인하는 짧은 사전 검토입니다.

## 반복으로 느껴질 수 있었던 부분

| 겹치는 소재 | 실제 겹침 | 12주차의 조정 |
|---|---|---|
| API·로그·지연 | 10주차에서 이미 정의·계측·오류 상태를 학습 | 23·25쪽을 사용자·실험·배정·결과 연결 키로 전환 |
| HTTP 실패 | 10주차에서 502/503/504와 복구를 학습 | 27쪽은 B 오류 사용자를 제외해 0%p가 +15%p로 보이는 분모 반례 |
| 지표의 분모 | 10주차 요청 분모, 11주차 평가 대상 분모 | 28쪽에서 진입→응답→피드백→해결 확인의 실제 합성 인원 흐름 |
| HOLD·REVIEW | 세 주차 모두 채택·보류를 표현 | 47쪽에서 상태 정리, 51쪽은 INCONCLUSIVE와 후속 설계로 전환 |
| 단계적 배포 | 10주차 65쪽에서 카나리 개념 소개 | 52쪽은 실험 대상·기간과 일반화 가능한 적용 범위 |
| 실제 출력의 품질 | 11주차에서 문자열 검사·사람 검토를 상세히 학습 | 53쪽·05번은 짧은 연결 확인, 54쪽은 피드백 UI에 의한 측정 변화 |
| 도구 역할 | 10주차 Prometheus·Trace, 11주차 Langfuse·LangSmith | 56쪽은 공용 캐시 때문에 배정과 실제 경험이 섞이는 설계 반례 |

같은 예시 서비스와 상태 이름은 연결을 위해 유지합니다. 설명의 중심은 **도구 재소개가 아니라 새 분석 단위·실패 유형·의사결정**입니다.

## 12주차에서 새로 집중할 내용

1. 사용자 고정 배정과 실험 진입 비율의 구분 — 9–15쪽, Notebook 01.
2. 사용자·배정·실제 제공·피드백의 연결 — 16–30쪽, Notebook 02.
3. SRM(Sample Ratio Mismatch)·수집 누락·응답자 선택 — 31–38쪽, Notebook 03.
4. 절대/상대 차이·신뢰구간·표본 계획·반복 확인·관찰 창 — 39–50쪽, Notebook 04.
5. 결론 유보·외적 적용 범위·피드백 계측·캐시 오염 — 51–58쪽.
6. 9–12주차 증거를 연결한 한 페이지 배포 판단 — 59–64쪽, 공개 과제.

## 수업 시작 설명 예시

“10주차에는 요청이 어디서 실패했고 복구됐는지를 확인했습니다. 11주차에는 서비스가 응답하더라도 그 답변이 틀릴 수 있어, 같은 질문으로 버전별 품질을 검사했습니다. 오늘은 그다음 질문입니다. 품질 기준을 통과한 변경이 실제 사용자에게도 도움이 되는지, 누구에게 어떻게 제공하고 어떤 결과로 판단할지 배우겠습니다.”
