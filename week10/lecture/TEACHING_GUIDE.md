# 10주차 · 76쪽과 100분 수업 진행안

## 목적과 자료의 역할

주제는 **LLM 서비스 배포와 실행 관찰**이다. 9주차 API 계약을 반복하기보다 실행 버전·계측·원인 탐색·복구·배포 판단을 연결한다. 76쪽은 강의와 복습 자료를 함께 담는다. 모든 장표를 같은 속도로 읽거나 전체 Notebook을 수업 중 완주하지 않는다.

| 시간 | 핵심 장표 | 진행 |
|---|---|---|
| 00–08분 | 1–8 | 200 응답의 잘못된 답변 사례·실제 화면·로드맵 |
| 08–20분 | 10–13·16·18·21–25 | 릴리스·환경·포트·준비 상태 |
| 20–30분 | 27–30·32–34·37–42 | 공식 도식·로그 연결·Span·실패 지점 |

| 40–45분 | 66–67 | 휴식·커널·서버 점검 |

Docker 명령과 전체 구현 읽기는 선택 복습으로 둔다. 공통 경로의 추가 설치를 유발하지 않는다. Notebook은 각각 독립 실행 가능하고 전체 권장 분량은 약84분이다.

## 도입 사례와 관찰의 질문

2쪽의 v2는 200이지만 잘못된 고정 답변을 반환한다. “이 버전을 배포할 수 있는가”를 학생에게 먼저 묻고, 서비스가 살아 있다는 증거와 내용이 요구사항을 만족한다는 증거를 구분한다. 실제 모델 정확도 시험이 아니라 명백한 회귀를 재현한 fixture임을 설명한다.

10–20쪽은 코드·모델·프롬프트·데이터·명세·실행 설정을 따로 기록한다. config_id는 허용 설정 JSON의 지문이고 Git commit이나 이미지 digest를 대신하지 않는다. 12–17쪽은 venv와 컨테이너의 경계를 비교한다. Docker 데몬 미기동으로 이미지 빌드·컨테이너 실기는 미검증이며 학생의 선택 실행 경로다.

## 상태 검사

21–24쪽은 Kubernetes의 검사 개념을 참고하지만 클러스터를 설치하지 않는다. 실습의 startup은 lifespan 상태이고, readiness는 started·draining·의존성 fixture의 조합이다. 검사 endpoint가 있다고 로드밸런서 정책이 저절로 구현되는 것은 아니다. 외부 의존성만 장애인 경우 프로세스 재시작을 반복하는 선택이 적절한지 질문한다.

## 로그와 Trace

28·30쪽은 OpenTelemetry 공식 원본 도식이다. 저자·라이선스·회색조 표시를 명시했다. 공식 도식의 분산 서비스 구조와 이번 한 프로세스의 직접 구현 계측을 혼동하지 않도록 설명한다. SDK·Exporter·Collector·백엔드 연결은 확장 주제다.

32–36쪽은 완료 로그의 허용 필드를 살핀다. message·answer·IP·예외 원문을 넣지 않는다. 보존 제한200건과 누적 counter는 범위가 다르다. request_id로 로그를 찾고 trace_id로 작업을 모은다. ID는 인증 증거가 아니다.

37–44쪽은 parent_id와 기간의 포함 관계를 확인한다. 입력 검증422는 endpoint 진입 전이라 로그만 있고 assist Span은 없다. 검색 오류는 generate를 실행하지 않는다. generate ERROR만으로 외부 GPU 작업이 취소됐다고 말하지 않는다. 교육용 traceparent 파서는 전체 W3C 구현이 아니며 샘플링 정책도 제공하지 않는다.

## 집계와 장애

46–54쪽은 전체 assist 요청에서5xx를 나누는 분모 정의다. 이번 분모에422는 포함되고 UI·프로브·스크레이프는 제외된다. histogram 버킷은 이하 누적 개수여서 단순 합산할 수 없다. 요청0을 성공100%로 읽지 않고, counter reset이 있으면 구간 차이 계산을 중단한다. 실제 SLO·장기 알림 임계값은 확정하지 않는다.

56–65쪽은 증상→근거→완화→재검증을 연결한다. Notebook05의 dependency_ok 변경은 로컬 테스트 fixture이며 운영 관리 API가 아니다. Notebook06의 v1 복원은 새 앱을 만들어 확인하는 로컬 비교다. 실제 Canary·Blue-Green·트래픽 전환을 완료한 것으로 소개하지 않는다. 200과 내용 기준을 동시에 보는 배포 gate의 이유가 핵심이다.

## 기획서 리뷰와 공지

68–71쪽은 사용자 문제·변경·시험·판단 근거를 연결한다. 단일 또는 복수 포트폴리오를 허용하고 결과물 수·도구 수를 자동 평가 점수로 쓰지 않는다. 실제 실행·고정 시안·목표·미측정을 나누어 기록한다.

**마지막 74–76쪽 공지:** 기획서2차는 **2026년11월6일(금) 오늘 제출**, 미제출자는 **늦어도11월7일(토)까지 제출 요청**이다. 확정되지 않은 마감 시각·감점 정책은 추가하지 않는다. 아주대AI대학원은LMS, 군산대·창원대 등 별도 수강생은 공지된 담당 교수 이메일을 이용한다. PPT·Word 기반PDF·HTML 등에서 선택하며 HWP/HWPX는 제외한다.

## 검증·재생성

```bash
python scripts/build_week10_notebooks.py
python scripts/verify_week10_notebooks.py
python scripts/verify_week10_live.py
```

차트 입력은 `lecture/assets/measurements.json`에 공개한 합성 실험의 필요한 집계다. 재측정 시 원시 receipt를 검토하고 날짜·단위·조건과 함께 입력을 갱신한 뒤 PPT·PDF를 재생성한다. 슬라이드 생성은 공통 빌드 환경에서 `scripts/build_course_deck.mjs 10`을 사용한다. 브라우저 캡처 스크립트는 Playwright와 실행 가능한 브라우저가 필요하며 `CHROMIUM_EXECUTABLE`로 설치된 실행파일을 지정할 수 있다. 학생 필수 도구가 아니다.
