# Week 10 · 기획서 개선안과 프로젝트 포트폴리오

[10주차 작성 양식 HTML](../curriculum/2026-2/web/project-portfolio-week10.html)을 내려받아 브라우저에서 작성한다. 기존 [Markdown 상세 템플릿](../curriculum/2026-2/02_기말프로젝트_기획서_템플릿.md)의 13–17절을 이용해도 된다.

## 작성할 내용

- 단일 프로젝트 집중 / 복수 프로젝트 병행 / 주력과 탐색을 조합한 포트폴리오 선택과 이유
- 프로젝트별 사용자·문제·BM 또는 재원·최소 기능·기술/데이터·평가·유지/중단 기준·10→16주차 결과
- ChatGPT·Codex·Claude 등 선택한 도구의 역할, 입력·제약·산출물, 작업 의존성과 사람 검수·통합
- 하루·주간 계획/실제 시간과 비용, AI 대기 시간 활용, 검수 가능량과 다음 조정
- 입력·정답·기준선·버전·목표/실측·실패·증거·채택/기각을 잇는 검증 기록

프로젝트 수에 자동 가산·감점을 두지 않는다. 단일의 개선 깊이와 통합 품질, 복수의 개별 검증·완성도와 선택·자원 배분·학습 근거를 함께 설명한다. 16주차 결과물은 하나 또는 여러 개 가능하며 유료 도구 사용은 필수가 아니다. 기존 피드백의 범위 조정은 각 실험의 핵심을 명확히 하자는 뜻이며 여러 주제 제출을 제한하지 않는다.

## 저장과 제출

1. GitHub 파일 화면에서 **Download raw file**로 HTML을 내려받아 연다.
2. 필요한 항목을 작성하고 프로젝트/표의 행을 추가한다. 모든 칸이나 여러 형식을 중복 제출할 필요는 없다.
3. **작성본 HTML 저장** 후 내려받은 파일을 다시 열어 입력과 추가 행이 남아 있는지 확인한다. JSON은 보조 기록용이다.
4. 인쇄 → PDF로도 보관할 수 있다. 내용이 길면 인쇄 미리보기에서 표·페이지를 확인한다.
5. 제출 경로와 정확한 마감은 소속별 최신 공지를 따른다. 이 양식으로 새 마감·수치 배점을 추가하지 않는다.

자동 저장되지 않는다. 작성본·개인정보·자격증명·허용되지 않은 자료는 공개 강의 GitHub에 올리지 않는다. 공개 저장소에는 빈 양식만 배포한다.

8주차 기획의 제품·기술·평가 내용을 재사용하고, 실제 수신한 피드백과 변경 전후를 연결한다. 계획·고정 시안·직접 실측은 구분해서 기록한다.
