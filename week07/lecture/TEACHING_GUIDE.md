## 현업 관점의 설명

- 기술 선택: 형식 실패라면 프롬프트와 출력 검증부터 비교한다. 최신 지식 문제를 미세조정으로만 해결하려 하면 수정·삭제 비용이 커질 수 있다. 반복 실패를 유형별로 나눈 뒤 최소 변경을 선택한다.
- 학습 자료: 예쁜 정답보다 대표 실패를 고치는 합법적이고 일관된 자료가 중요하다. 문장 중복뿐 아니라 사건·시간 누출도 점검한다. 자동 검사는 내용의 신뢰성과 사용 권한을 대신 승인하지 않는다.
- LoRA: 두 행렬의 파라미터 절약을 먼저 계산하되 실제 메모리는 activation·optimizer까지 측정한다. 이번 SVD는 구조를 보여주는 도구일 뿐 실제 학습 알고리즘과 결과가 아니다.
- DPO: chosen은 무조건적인 진실이 아니라 해당 기준의 상대 선택이다. 길이·순서 편향을 분리하고 유용성과 과도한 거절을 따로 본다. reference 대비 시퀀스 log probability를 사용하며 Judge 점수를 수식에 넣지 않는다.
- 기획: 첫 문단에서 제안과 범위를 읽을 수 있어야 한다. 제작 과정·도구 대화는 부록으로 이동한다. 성공 기준·실패 처리·데이터 권한·검증 비용이 없는 시안을 완성 서비스로 평가하지 않는다.

## 기획서 리뷰 진행

1. 현재 버전·사용자·문제를 30초로 설명한다.
2. 사업 가치·사용 경험·구현 가능성 가운데 가장 불확실한 질문을 고른다.
3. 교수는 근거·범위·평가·위험을 확인한다. 답을 대신 작성하지 않는다.
4. 학생은 채택·보류·반박과 이유를 기록하고 추가 검증을 정한다.
5. 8주차 수정본에 변경 전후와 근거를 연결한다.

아주대 팀 2–4인, 타교 개인 진행 가능을 기본으로 안내하되 개별 승인과 소속별 평가 적용은 별도 확인한다. 명단·메일·팀 배정 상황은 학생용 장표에 넣지 않는다.
