## 실제 플랫폼과 변경 검증

Docker Compose 여섯 서비스(web, worker, PostgreSQL, ClickHouse, Redis, MinIO)의 정상 기동과 UI 로그인을 확인했습니다. Ollama는 호스트에서 실행하며 모델을 컨테이너에서 부르는 구조가 아닙니다. `.env`는 로컬에만 생성하고 Git에서 제외했습니다.

| 비교 | 인용·기권 계약 검사 | 답변 불가 수락 | 교육용 배포 판단 |
|---|---:|---:|---|
| A 기준선 | 75% | 1건 | 비교 기준 |
| B 근거 제한 프롬프트 | 75% | 1건 | HOLD |
| C 기능 정책 | 100% | 0건 | REVIEW |

선택한 합성 회귀 사례 4건의 실제 결과입니다. 의미 정확도·일반화된 서비스 품질·속도 개선으로 해석하지 않습니다. C의 재고 경로는 기능 정책 응답이고 생성과 모델 평가는 수행하지 않습니다. 다른 정상 사례 3건은 실제 Ollama를 호출합니다. 자유형 의도 분류기는 구현하지 않았습니다. 작은 모델의 잘못된 답과 judge 판정도 공개 비교 결과에 그대로 포함합니다.

`release_decision`은 다른 데이터 세트, 문항 누락·중복, 빈 검사·잘못된 출력·NaN 지연을 통과시키지 않습니다. 필수 실패를 judge 점수로 덮어쓰지 않으며 REVIEW 이후에도 자동 배포는 없습니다.

## 발표 UX 개정 검증

원래 52쪽에 실제 플랫폼 실습 12쪽을 통합하여 64쪽으로 구성했습니다. PDF는 Chrome 인쇄 엔진으로 생성하고 Poppler로 전체 페이지를 렌더해 검토합니다. 4·5·21·44쪽의 단계별 흐름, 학습 단계 이동, 검색 가능한 목차, 원본 이미지 확대·스크롤, 동작 감소와 인쇄 상태를 검증합니다. 320·390·768·1024·1280px 너비와 1440×600px 짧은 화면에서 64쪽을 검사했고 가로 넘침은 없었습니다. 휴대폰·태블릿은 문서 배치로 전환하고 표에 열 이름을 표시합니다. 다음 장표는 맨 위에서 시작합니다.

독립 시각 검수 후 실제 점수 로딩 완료 캡처, 핵심 영역 확대, 1100px 반응형 전환, 모바일 관계 설명을 수정했습니다. Hallmark 정적 검사: FAIL 0. 전체 단어 수·서로 다른 열 간격의 WARN은 64쪽 강의의 장표별 역할에 따라 유지했습니다. Impeccable의 slide 패딩 경고는 실제 계산된 72px(데스크톱)·24px 이상(읽기 모드)과 렌더를 확인했습니다. Hallmark 자체 render tier는 puppeteer-core 부재로 실행되지 않았고, 별도 Playwright 검증 결과를 사용합니다.

`lab/demo/`는 학생 공유용 안내, `lab/reports/langfuse/instructor-console.html`은 실제 실행 ID가 있는 개인용 안내입니다. 후자는 Git 제외입니다. 공개 샘플에는 교수 작성 합성 사례만 사용했습니다.
