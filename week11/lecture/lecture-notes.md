# 11주차 강의 노트

## 01. LLM 서비스의 품질 검증

오늘은 검색 점수부터 실제 LLM 답변, 평가자의 오판, 실행 기록까지 확인한다. 특정 도구 이름이 목적이 아니라 변경을 검증하는 흐름이 목적이다. Core AI PM은 핵심 인공지능 제품 관리 역할이다.


## 02. 16주 과정의 현재 위치

6주차는 녹화영상과 신규 과제도 없었다. 8주차는 중간고사 없이 제출물 평가였으며 10월22일23:59 마감이었다. 16주차는 온라인 실시간 발표다. 오늘은 11주차 평가 데이터를 프로젝트 증거로 추가한다.


## 03. 100분 수업의 진행

모든 셀을 동시에 설명하지 않는다. 03의 계산 심화는 필요한 경우만 열고, 07과 08은 반드시 실제로 실행한다. 수업 전 모델 다운로드를 마친다. 시간 부족 시 준비된 실제 실행 보고서를 보되 실시간 실행으로 소개하지 않는다.


## 04. LLM 서비스와 평가 지점

모든 서비스에 적용되는 단일 표준 도식은 없다. 공식 문서의 데이터·실행·평가 구조를 RAG 사례로 재구성했다. 검색 문서가 맞아도 생성 단계에서 조건을 빠뜨릴 수 있다. 운영에서는 권한, 비용, 안전 검사를 서비스 요구에 맞춰 추가한다.

출처: https://docs.langchain.com/langsmith/evaluation-concepts

## 05. 배포 전 평가 아키텍처

MLflow는 dataset, predict function, scorers로 평가 실행을 설명한다. LangSmith도 example의 reference outputs를 애플리케이션에 전달하지 않고 evaluator에서 사용한다. 실습 ollama_lab.py도 gold_ids와 reference를 생성 프롬프트에서 제외한다.

출처: https://mlflow.org/docs/latest/genai/eval-monitor/

## 06. Trace와 Span의 역할

OpenTelemetry의 trace는 관련 span의 연결이다. 본 수업 JSON trace는 그 관계를 배우는 로컬 기록이며 OpenTelemetry 표준 전송 형식 자체는 아니다. 응답 지연만 보고 정답 여부를 알 수는 없다.

출처: https://opentelemetry.io/docs/concepts/signals/traces/

## 07. 서비스 사례와 성공 조건

실제 무신사 정책이나 법률 안내가 아니다. 학습을 위해 만든 가상 쇼핑 정책임을 분명히 말한다. 사용자 질문은 한 문장이지만 필요한 근거는 여러 개일 수 있다.


## 08. 질문과 참고 기준의 구조

reference는 검토용이다. 검색기에 넣으면 정답을 입력으로 제공하는 오류다. gold 문서가 실제 존재하는지 자동 검증한다.


## 09. 문서 버전과 정답 근거

잘못된 답이 반드시 모델 환각은 아니다. 잘못된 버전의 검색 근거에서 출발할 수 있다. status와 version을 색인 계약에 포함한다.


## 10. 답변할 수 없는 질문

문서에 답이 없으면 검색기가 비슷한 문서를 찾아도 정답 근거가 아니다. 이 실습은 기권 정책만 검사하며 실제 외부 조회를 수행하지 않는다.


## 11. 개발 세트와 평가 세트의 분리

같은 의도의 정중한 질문과 구어체 질문은 같은 split에 둔다. 문서 집합은 공유하며, 새로운 도메인 적응 실험으로 주장하지 않는다. Notebook01은 각 세트의 24문항·12의도와 그룹 교집합이 없음을 검증한다. 잘못된 split을 입력한 누수 차단 메시지는 의도한 실험 결과다.

출처: https://scikit-learn.org/1.7/common_pitfalls.html#data-leakage

## 12. 실습 01: 데이터 계약 검증

Notebook의 try/except가 예상 오류를 잡으므로 전체 실행이 멈추지 않는다. 코드를 고치기 전에 데이터 구조를 읽게 한다.


## 13. 단어 검색과 문자 검색

문자 방식이 모든 질문에서 우월하다고 결론내리지 않는다. 예를 들어 의미가 비슷하지만 문자열이 다른 질문은 두 방식 모두 어렵다.

출처: https://scikit-learn.org/1.7/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html

## 14. 한 요소씩 바꾼 비교

threshold=0인 상태에서 문서 필터와 analyzer를 한 요소씩 바꿨다. 정확한 실험 조건을 함께 말해야 수치의 원인을 설명할 수 있다.


## 15. 복수 근거 질문의 성공 조건

초기 AS-IS 실습의 단일 정답에서는 Hit와 Recall이 같아 차이를 보기 어려웠다. 복수 근거로 지표의 의미를 구분한다.


## 16. 검색 개수와 지표의 변화

정답은 A와 B다. k=3일 때 Recall=0.5, k=4일 때 Recall=1이다. 첫 정답 순위는 2이므로 MRR=0.5로 유지된다. 학생이 값을 바꾼 뒤 변화 이유를 말하도록 한다.


## 17. MRR과 nDCG의 차이

Notebook03은 nDCG를 손계산하고 sklearn과 대조한다. 정답이 아예 없는 질문의 Recall은 None이고, 정답은 있지만 못 찾은 경우는 0이다. 여러 문서가 필요한 문제는 Hit만으로 완전성을 판단할 수 없다.

출처: https://scikit-learn.org/1.7/modules/generated/sklearn.metrics.ndcg_score.html

## 18. 검색 개수에 따른 지표 변화

x축은 표시한 k의 이산 범주다. 점을 이은 선은 추세를 읽기 위한 안내다. LLM의 토큰 비용과 생성 정확성은 이 그래프에서 측정하지 않았다.


## 19. 긴 문맥과 답변 품질의 관계

Lost in the Middle 연구는 당시 모델과 과업에서 관련 정보 위치에 따른 성능 변화를 관찰했다. 이 그림은 위치 조건을 설명한 재구성 도식이며 논문 성능 곡선을 복제한 것이 아니다. 최신 모든 모델에 같은 수치가 적용된다고 말하지 않는다.

출처: https://arxiv.org/abs/2307.03172

## 20. 검색 실습의 확인 지점

02는 빈 검색 []와 동점 정렬 A,B도 확인한다. 03은 None과 0, 중복 ID 차단을 확인한다. 시간 제약이 있으면 실습 안내에 있는 결과표로 대조하고 계산 심화는 복습으로 진행한다.


## 21. 응답과 기권의 판단 흐름

## 22. 임계값과 사용성의 변화

파랑이 항상 좋아야 하는 그래프가 아니다. 답변 불가 수락률은 낮을수록 좋다. 근거 확보율의 감소는 기권 정책과 연결된다.

## 36. 작은 모델 평가자의 실제 판정

실습의 10%와 80%는 교육용 기준이며 보편적인 산업 표준 수치가 아니다. 파이프라인을 코드로 연결할 때 --enforce-gate는 HOLD에 종료 코드2를 반환한다. REVIEW라도 자동 배포 명령은 없다.

## 47. 평가 보고서의 실제 화면

이 화면은 실제 TF-IDF 평가 보고서다. Ollama 생성 보고서는 별도 파일이며 점수나 run_id를 혼합하지 않는다. 앞에서 원인을 살펴본 Q24a를 필터로 다시 찾는다.


## 48. 실습 06: 보고서 재생성과 확인

기본 CLI의 HOLD는 정상 결과다. --enforce-gate 옵션만 종료 코드2로 차단한다. Ollama CLI는 모델의 의미 오류를 테스트 실패처럼 숨기지 않고 실제 출력과 판정을 저장한다. 두 보고서는 평가 범위가 다르다.
