# 11주차 HTML 프레젠테이션 디자인

대상은 특정 학교에 한정하지 않는 대학생·대학원생 통합 강좌입니다. 실시간 온라인 화면 공유로 이해하고, 수업 후 PDF와 Notebook으로 재현합니다. 사용자가 이미 정한 블랙·화이트·블루와 명사형 제목, 충분한 글자 크기를 기준으로 확장했습니다.

## 표현과 토큰

- 배경: 흰색, 장 구분: 네이비. 의미가 있는 수치·현재 위치만 파랑.
- 글꼴: 라이선스를 포함한 Pretendard Regular/Bold, 코드만 monospace.
- 1440×810 슬라이드: 제목 46px, 본문 24px, 표 21–23px, 출처 16px.
- 본문은 과도한 축약 대신 입력·판단 기준·실패 사례를 구체적으로 설명합니다.
- 순서가 있는 과정만 번호를 사용합니다. 화살표를 긴 문장 연결에 사용하지 않습니다.
- 똑같은 카드의 반복을 피하고 비교표·흐름·데이터 계약·계산·실험 차트·연구 그림·실제 화면·질문으로 구조를 바꿉니다.
- 10개 Notebook 진입 장표는 학습자가 실행·확인·변경을 찾기 쉽도록 일관된 형식을 유지합니다.

## 기능

키보드 이동, 목차, 페이지 번호, 설명 노트, hash 복원, 그림 확대, 전체 화면, 전체 인쇄.
이미지·폰트·CSS·JS를 내장하여 HTML 하나로 공유합니다.
모바일에서는 강제 축소 대신 세로 배치하고 차트는 수치 표로 제공합니다.
JS 없이도 64쪽을 문서 순서로 읽을 수 있습니다.

## Impeccable·Hallmark 적용

공식 지침의 내용 우선·시각 위계·토큰·대비·여백·상태·실제 렌더 검수 원칙을 사용했습니다.
새 브랜드 선택이나 재승인을 요구하는 흐름은 사용자가 이미 제시한 방향에 따라 반복하지 않았습니다.
웹사이트용 6–9개 섹션, 마케팅 행동 유도, 사진 요구는 64쪽 수업 자료에 적용하지 않았습니다.

이번 개정은 Impeccable distill 지침에 따라 반복 정의를 통합하고, 64쪽의 단계별 목차와 실제 서비스 도식을 추가했습니다.
Hallmark 정적 검사에서 색상 리터럴·간격·범위 표기를 정리했습니다.
흰 배경은 사용자의 명시적 팔레트이므로 absolute surface로 기록했습니다.
Hallmark 자체 render tier는 로컬 puppeteer-core 부재로 실행되지 않았으며, 이를 통과했다고 표시하지 않습니다.
별도 Playwright/Chrome으로 64쪽, 모바일, 키보드·목차·그림 확대·인쇄·보고서 기능을 검증했습니다.
초기 버전의 독립 검수에서 지적된 가독성 기준을 유지합니다. 개정판에서는 화살표와 라벨의 간격, 참고 기준의 별도 흐름, 제품 화면 확대와 모바일 대체 텍스트를 점검합니다.

## 재생성

1. python -m week11.lab.run_eval --out week11/lab/sample
2. python -m week11.lab.ollama_lab --limit 3 --judge --out week11/lab/sample/ollama
3. node scripts/capture_week11_lab.mjs
4. python scripts/build_week11_html.py
5. node scripts/verify_week11_browser.mjs

Node 검증 스크립트는 개발자용 Playwright와 설치된 Chrome을 사용합니다.
학생 실습에는 Node나 Playwright가 필요 없습니다.
PDF는 HTML의 print CSS와 Chrome 인쇄 엔진으로 생성하며 모든 페이지를 점검합니다.

## 계층과 근거

서비스 구조 → 평가 데이터 → 검색 비교 → 실패 분석 → 실제 생성 → 평가자 → 운영 도구 → 배포 판단 순서입니다. 100분 중 실제 Ollama 생성·평가, 09 요청 추적 20분, 10 실험 비교 25분을 배정합니다. 자세한 코드와 조건은 Notebook·WALKTHROUGH.md·설명 노트로 이어집니다.

핵심 SVG는 서비스 구조, 두 버전의 평가, 기권 분기, LangSmith 실험 비교, 배포 승인 흐름입니다. 사각형은 처리·산출물, 마름모는 배포 기준 판단에 사용합니다. 출처 기반 재구성이며 단일 산업 표준이라고 주장하지 않습니다.

64쪽의 내용 구성은 `scripts/week11_refinement.py`, 기존 설명·도식 생성 함수는 `scripts/build_week11_html.py`에서 관리합니다. 생성 보고서의 실패·오판도 실제 출력 그대로 반영합니다.

## 실제 플랫폼 화면 추가

12쪽을 추가하여 64쪽으로 구성했습니다. 46·47·51쪽은 실제 로컬 Langfuse 화면이며, 확대 기능을 제공합니다. `scripts/week11_langfuse_slides.py`가 원래 52쪽 흐름에 실제 실행 구조·화면·실험·배포 판단을 통합합니다. `scripts/build_week11_langfuse_casebook.py`는 합성 실행 결과의 공개 비교 페이지를 생성합니다.


## 컨퍼런스 발표 UX 개정

- **시각적 중심:** 실제 응답 → 비교 실험 → 배포 판단. 표지는 질문과 학습 산출물을 나누고, 43쪽 실습 미션은 네이비 배경으로 설명에서 실행으로의 전환을 표시합니다.
- **의미 있는 움직임:** 4·5·21·44쪽의 ‘흐름 보기’는 발표자의 입력으로 관련 노드만 강조합니다. 이전/다음 단계와 전체 보기를 지원하며 F 키로 진행합니다. 자동 반복·장표마다 같은 등장 효과는 없습니다.
- **연속성:** 상단 학습 단계 이동, 검색 가능한 목차, 페이지 hash 복원. 핵심 서비스 흐름에서 현재 장으로 쉽게 돌아갑니다.
- **반응형:** 1100px 이하 또는 높이 640px 이하에서는 고정 캔버스를 축소하지 않고 읽기용 배치로 전환합니다. 휴대폰의 표는 열 이름이 붙은 행 단위로 재배치합니다.
- **도식 접근성:** 주요 분기의 모바일 대체 설명에 두 버전의 병렬 실행, 참고 정답의 별도 경로, 모델 호출과 기록 전송의 차이를 보존합니다.
- **실제 화면:** 46·47·51쪽은 저장 완료 이후 실제 화면의 핵심 영역을 캡처하고 큰 설명을 병치합니다. 그림 확대의 ‘원본 크기’에서 스크롤로 읽습니다.
- **동작 감소·인쇄:** reduced-motion에서는 즉시 상태 변경. 인쇄와 JS 없는 문서에는 전체 구조가 표시되며 단계별 흐리기나 조작부가 남지 않습니다.

Impeccable 4.8.2의 layout·animate·craft-floor를 참고했습니다. layout 지침에 따른 독립 시각 검수에서 지적된 로딩 중 캡처, 태블릿 축소, 모바일 관계 손실, 작은 확대 화면을 수정했습니다. Hallmark 2.0의 토큰·읽기 위계·실제 자료·상태 원칙을 적용한 기존 디자인 개선이며, 새 테마 전체 제작 절차를 수행한 것으로 주장하지 않습니다.

## 전체화면 배율과 발표 메뉴

일반 보기의 읽기 배치와 전체화면 발표 배치를 분리합니다. Fullscreen API 진입 시 배율은 `min(화면 너비 / 1440, 화면 높이 / 810)`이며 100% 상한과 메뉴용 여백을 제거합니다. 장표는 중앙 정렬하고 16:9 비율을 보존합니다. 일반 보기로 돌아오면 태블릿·모바일의 읽기 배치가 복원됩니다.

메뉴는 약 2.2초 뒤 숨기며 화면 위·아래 가장자리의 포인터, 터치 또는 키보드 포커스로 표시합니다. P로 전체화면 전환, Esc로 종료, F는 도식의 다음 단계입니다. Cmd/Ctrl+P 인쇄 단축키를 가로채지 않습니다. Fullscreen API가 제한된 호스트에서는 창 안의 발표 모드로 전환하고 제한 및 복귀 방법을 표시합니다. 인쇄에는 이 화면용 배치가 적용되지 않습니다.
