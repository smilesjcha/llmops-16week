HOLD와 REVIEW: 자동 판정의 다음 행동

결과정확한 의미교수 설명 예시다음 행동
HOLD · 보류필수 조건 실패, 서로 다른 데이터, 누락·실패한 실행 등“지시를 고쳤지만 재고를 알 수 없는 요청을 수락했습니다. 이 변경은 보류합니다.”실패 checks와 원본 trace 확인 → 원인 수정 → 같은 데이터 재평가
REVIEW · 검토 대기자동 조건은 통과했으며 사람 검토로 이동“C는 네 사례의 계약 검사를 통과했습니다. 실제 내용과 추가 경계 사례를 확인하겠습니다.”의미 품질·위험·범위 검토 → 별도 승인 판단

둘 다 자동 배포 승인이 아닙니다. 이 이름과 기준은 수업의 release_decision 함수가 정의한 정책이며 Langfuse의 내장 승인 상태가 아닙니다.

  1. 같은 데이터셋의 네 질문이 빠짐없이 정상 실행됐는지 확인
  2. 답변 불가 수락 0건, 적용되는 계약 검사 통과율 100%
  3. 기준선 대비 계약 검사 통과율 저하 없음
  4. 단일 생성 호출의 최대 시간 3000ms 이하
  5. 모든 조건을 통과하면 REVIEW, 그렇지 않으면 HOLD

3000ms는 결과를 보기 전에 정한 수업용 예산입니다. 실제 제품에서는 요구사항에 맞춰 정합니다. 여기서 최대 시간은 네 요청 중 최댓값이며 p95라고 부르지 않습니다.

이름이 비슷한 두 REVIEW

예상과 다른 결과가 나왔을 때
