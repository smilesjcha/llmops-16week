# 11주차 100분 교수 진행안

핵심 질문: **검색 점수가 좋아졌는데도 왜 배포를 보류하는가?**

| 시간 | 장표 | 진행 |
|---|---|---|
| 0–8분 | 1–10 | 실제 HOLD 결과부터 질문, 16주 흐름과 평가 단위 |
| 8–20분 | 11–25 | 데이터 기준과 누수, Notebook01 핵심 셀 |
| 20–30분 | 26–33 | 단어/문자 기준선·필터, Notebook02 비교 |
| 30–42분 | 34–41 | k 슬라이더, 지표 손계산, Notebook03 핵심 |
| 42–63분 | 42–50 | 임계값·test·말투별 실패, Notebook04 |
| 63–80분 | 51–61 | 답변 평가·판정 오류, Notebook05 |
| 80–94분 | 62–70 | CI/보고서·배포 판단, Notebook06 |
| 94–100분 | 71–76 | 프로젝트 적용, 자기 점검, 질문 |

76쪽을 같은 속도로 읽지 않습니다. 22·25·29·32·36·54·58·60·64·68·74–76쪽은 사전 읽기/심화/참조로 짧게 활용할 수 있습니다. 수업 시간이 부족하면 모든 셀을 수정시키지 말고 기본 실행 후 핵심 변화 하나만 확인합니다.

## 수업 전 5분 점검

1. 기존 Python 3.11 환경에서 requirements/week11-offline.txt 설치.
2. python -m week11.lab.run_eval 실행, report.html 열기.
3. HTML 강의안을 브라우저에서 열고 34쪽 슬라이더와 설명 노트 확인.
4. sample/report.html을 예비 시연 자료로 준비. 이는 실제 실행한 합성 데이터 결과입니다.
5. GitHub HTML은 실행되지 않으므로 학생에게 다운로드 후 여는 방법 안내.

- 70쪽: 프로젝트의 결론과 근거를 한 페이지로 설명할 수 있는가?

## 혼동 방지

- 가상 정책은 실제 무신사나 다른 회사의 정책이 아닙니다.
- TF-IDF는 실제 실행되지만 LLM 생성·임베딩·LLM judge는 기본 경로에서 호출하지 않습니다.
- judge 표는 작성 fixture 계산입니다. 연구 결과나 인간 주석가 실험이 아닙니다.
- ARES 그림은 원 논문 자료이고, 수업 실습은 ARES/PPI 재현이 아닙니다.
- bootstrap은 8개 답변 가능 의도 그룹의 제한된 비교입니다.
- CI는 문맥에 따라 Confidence Interval(신뢰구간) 또는 Continuous Integration(지속적 통합)입니다. 장표에서는 한글 또는 전체 명칭으로 구분합니다.
- 이번 자료는 신규 과제 마감·배점을 추가하지 않습니다. 10주차 제출 안내를 ‘오늘 마감’으로 재사용하지 않습니다.

강의 노트는 HTML의 설명 노트 버튼 또는 lecture-notes.md에 있습니다.
