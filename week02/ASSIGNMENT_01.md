## 진행 순서

1. [VS Code 실행 가이드](VS_CODE_GUIDE.md)를 따라 실습 화면을 엽니다.
2. `Demo`에서 합성 문의 T01–T08 8건과 v1·v2·v3를 비교합니다. 결과는 총 24건입니다.
3. 실패 사례 1건을 열어 문의 원문, 기대 결과, 실제 응답과 검사 이유를 확인합니다.
4. 선택할 버전 또는 선택을 보류할 이유를 화면에 입력하고 **결정 기록 추가**를 누릅니다.
5. **JSON 보고서 내보내기**를 누른 뒤 파일을 열어 비교 결과와 선택 근거가 함께 저장됐는지 확인합니다.
6. 아래 질문에 답하는 분석 문서를 작성하고 PDF로 저장합니다.
7. 두 파일이 정상적으로 열리는지 확인한 뒤 소속별 제출 경로로 제출합니다.

서버를 종료하거나 재시작하면 화면의 실험 기록이 사라집니다. **JSON 파일을 먼저 내보내고 서버를 종료합니다.**

## 분석 문서의 네 가지 질문

### 1. 어떤 실패가 있었나요?

- 문의 번호와 프롬프트 버전을 적습니다. 예: `T03 / v2`.
- 기대 결과와 실제 응답에서 다른 부분을 짚습니다.
- 형식 오류인지, 분류·업무 규칙 판단 오류인지 구분합니다.
- 자동 검사 결과만 옮기지 말고, 사람이 읽었을 때 왜 문제가 되는지 설명합니다.

### 2. 어떤 버전을 선택하고 싶나요?

- v1·v2·v3의 지시·출력 형식·예시 중 무엇이 다른지 비교합니다.
- 지금 선택할 후보와 그 이유를 적습니다. 아직 선택하기 어렵다면 보류 이유도 가능합니다.
- 이 결과만으로 실제 서비스에 적용해도 되는지, 무엇이 부족한지 적습니다.

### 3. 다음에는 어떤 문의로 확인할 건가요?

- 기존 8건과 다른 **합성 문의 1건**을 직접 만듭니다.
- 기대하는 `category`, `priority`, `needs_review`와 그 판단 이유를 적습니다.
- 어떤 모호함이나 실패 가능성을 확인하려는 사례인지 설명합니다.
- 새 사례를 실제로 실행하지 않았다면 **“검증 계획 · 미실행”**으로 표시합니다. 실행 결과를 만들어 쓰지 않습니다.

### 4. 교수에게 무엇을 묻고 싶나요?

- 실험·평가·업무 규칙 중 이해가 어렵거나 의견을 듣고 싶은 질문 1개를 적습니다.
- 예: “교환과 환불이 함께 있는 문의를 첫 요청으로 분류하는 기준이 실제 서비스에서도 적절할까요?”

## Demo와 실제 모델의 구분

필수 과제는 API(Application Programming Interface) 키나 모델 설치 없이 **Demo만으로 완료**할 수 있습니다. Ollama는 선택 실습입니다.

Demo는 수업용 고정 응답을 재생합니다. 세 버전의 결과 차이는 이미 정해진 예시이며, 실제 대규모 언어 모델(Large Language Model, LLM)의 성능 측정값이 아닙니다. 프롬프트 파일을 수정해도 Demo 응답은 바뀌지 않습니다. 이 경우 변경된 지시와 확인하려는 효과를 **개선안**으로 적고, 실제 개선이 검증됐다고 쓰지 않습니다.

Ollama로 추가 실험한 경우에는 Demo 결과와 구분하고 모델명, 실행 조건, 실제 성공·실패·미실행 건수를 함께 적습니다. 설치 실패나 장비 성능 때문에 선택 실습을 하지 않아도 필수 과제는 제출할 수 있습니다.
